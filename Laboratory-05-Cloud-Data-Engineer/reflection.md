# Mission 5 Reflection

Object storage is more better for storing millions of photos compared to a traditional block storage hard drive because it can handle a very large amount of files without depending on only one disk or server. Each photo is stored as an object with its own metadata and unique key inside a bucket. This makes it easier to organize and access many photos, especially when the amount of data keeps growing. Block storage is very fast and useful for databases and virtual machines, but for millions of photos and other unstructured files, object storage is more suitable.

Using Docker made deploying MinIO much easier compared to installing it manually. Instead of installing many dependencies, configuring folders, and setting up the server one by one, I only need to use a Docker command with the required settings and credentials. After running the command, the MinIO server was already working. Docker also makes it easy to stop, remove, and run the container again if there is a problem. Because of this, I learned that containers can make deployment faster and more organized.

A bucket in cloud storage is like a main folder where objects or files are stored. Before uploading files, we need to create a bucket first, like the `client-photos` bucket that we created in this laboratory. The objects inside the bucket have their own unique keys, and the bucket can also have its own permissions and settings. This helps in managing and controlling the files stored in cloud storage.

Large companies protect their data from physical server failure by using replication and erasure coding. This means that the data can be copied or divided into different parts and stored in different drives or servers. If one server or hard drive suddenly fails, the data can still be recovered from another location. This is important because companies cannot afford to lose important data because of only one hardware failure.
